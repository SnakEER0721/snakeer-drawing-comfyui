====== ComfyUI 二次元出图 · 高频词表 ======

适用底模：Illustrious-XL（本机已装）
词表来源：本地数据库 328,023 条 + 内置整理词库 + 人工补充映射
验证状态：全部词条逐条程序化实测，100% 可翻译（0 失败）

用法
    在 UI 的提示词框里写中文，用逗号或空格分隔，程序自动转英文标签。
    例如输入「少女 半身 微笑 银发红眼」
    → 1girl, upper body, smile, silver hair, red eyes
    中英混写也支持，右边的英文标签同样可以直接写。

三条规则
    1. 重要的标签放前面（越靠前权重越高）
    2. 标签数量**分两种情况，别一刀切**（2026-09-17 修正）：
       · 照着已有的图还原（复刻构图 / 角色 / 氛围）→ **越完整越好**，
         40 个也不嫌多。这种场景下每个标签都是"这张图里确实有的东西"，
         它们互相印证、把画面收得更紧，不是互相稀释。
         用户实测：同一张图按完整版写 48 个标签，还原度和细节
         明显好于精简到 15 个。
       · 凭想象从零创作 → 8–15 个更稳。这时候多写的每一个标签都是
         你没验证过的猜测，堆多了容易互相打架、或引入不想要的细节。
       · 依据：SDXL 超 77 token 是**分块不是截断**（见后面「token 预算」一节），
         所以"装不下"从来不是限制；限制来自"标签准不准"。
    3. 看到「未收录」就换个说法，那部分不会进入模型

怎么找词
    一         构图与取景（人数、取景范围、局部特写、裁切出框、视角与角度、
               透视与镜头、景深虚化、构图手法、三分法、视线）
    二         画风与媒材（上色、笔触、网点、年代风格）
    三         视角与朝向（正侧背、俯仰、回眸）
    四~十四    按主题分类的主题词（发色、发型、眼睛、表情、服装、姿势、
               身体、背景、光影、画质、NSFW）
    十五       局部重绘（修图）专用：参数与提示词模板
    十六~二十一 质量词、其余要点、权重语法、参数、LoRA、放大
    二十二     无对应标签的专名，仅作记录
    各章的「◆」小节是细分类，章末的「补充」来自旧速查表，都可直接查用。
    直接想开写的话，跳到下面的「提示词模板（公式）」。


═══════════════════ 提示词模板（公式） ═══════════════════
2026-09-16 加入。每个词都逐条实测过，可直接抄。

【核心认知】
  在 Danbooru 系模型里，「光影美」「构图好」「透视惊艳」全都是**标签**，
  不是形容词。写 beautiful lighting / amazing perspective 一点用没有 ——
  那些词要么不存在，要么是 0 帖空标签。
  必须写**具体、可判定**的东西。

【填空模板】
  【自动】masterpiece, best quality, 1girl, solo   ← 程序替你加，别重复写
    ↓ 以下自己填。照着现有图还原 → 写满（40 个也不嫌多）；
      凭想象创作 → 8–15 个。详见上面「三条规则」第 2 条
  【取景】全身 / 半身 / 特写 / 远景
  【视角】低角度 / 仰视视角 / 高角度 / 荷兰角
  【透视】透视收缩 / 消失点 / 鱼眼
  【构图】负空间 / 剪影 / 对称
  【主体】发色 + 发型 + 服装
  【动作】姿势 + 表情 + 视线
  【光影】光源 + 方向 + 对比度          ← 三件套，见下
  【环境】地点
  【氛围】景深 / 背景虚化 / 速度线

  顺序原则：越靠前越重要，把最想要的三个效果放最前面。

【光影 = 光源 + 方向 + 对比度（三件套）】
  光源    丁达尔光(sunbeam 13355) / 镜头光晕(lens flare 50704) /
          黄金时刻(golden hour 384) / 阳光 / 月光 / 霓虹灯
  方向    逆光(backlighting 45726) / 侧光(sidelighting 13233)
  对比度  明暗对比(chiaroscuro 444) / 高对比 / 柔和光线
  ⚠ 死标签别用：轮廓光(rim lighting 查无此名) / 体积光(volumetric
    lighting 查无此名) / 暗黑(dark theme 0 帖)

【透视 = 视角 + 手法 + 取景（三件套）】
  视角    低角度/仰视视角(from below) / 高角度/俯视视角(from above) /
          荷兰角(dutch angle) / 鱼眼(fisheye 6804) / 平视角度
  手法    ★透视收缩(foreshortening 69968) ← 最有效 / 消失点 /
          强制透视 / 透视(perspective)
  取景    全身 / 半身 / 远景 / 大远景
  ★ 想要「眼前一亮」就用这一组：低角度 + 透视收缩 + 消失点
    foreshortening 就是「镜头怼近、物体夸张变形」的效果，
    它比任何形容词都管用。
  ⚠ 超广角不能用（wide angle 是 0 帖空标签），要广角感用「鱼眼」或「透视」

【构图 = 取景范围 + 空间处理】
  ★负空间(negative space 1745) = 留白。最容易被忽略、但对「好构图」最有效
  剪影 / 对称 / 不对称 / 画框 / 边框 / 取景框 都可用
  ⚠ 三分构图不能用（rule of thirds 不存在）

【细节：别堆 detailed】
  极高细节 / 细节丰富 / 超高分辨率 三个就够。
  真正的细节来自**景深 + 取景** —— 景深 + 背景虚化 让主体跳出来，
  比堆十个细节词有效。
  ⚠ 浅景深不能用（shallow depth of field 线上不存在），用「景深」就行

【一套可直接抄的例子】（目标是细节构图 + 光影 + 强透视）
  少女, 单人, 银发, 长发, 白衬衫, 百褶裙, 校服,
  低角度, 透视收缩, 消失点, 负空间,
  回头, 看向观众, 微笑, 风吹,
  逆光, 丁达尔光, 明暗对比, 镜头光晕, 黄金时刻,
  城市街道, 远景, 景深, 背景虚化, 速度线
  译文：1girl, solo, silver hair, long hair, white shirt, pleated skirt,
        school uniform, from below, foreshortening, vanishing point,
        negative space, looking back, looking at viewer, smile, wind,
        backlighting, sunbeam, chiaroscuro, lens flare, golden hour,
        city, street, wide shot, depth of field, bokeh, speed lines

【配套参数】
  采样器 dpmpp_2m + 调度器 karras（已是默认）
  steps 30 · CFG 5.5 · Clip skip 2 · 分辨率 1152×832（横向，为透视留空间）

【想更强就把关键词加权】
  (((透视收缩))), 低角度, 消失点     ← 只给 2–3 个词加权，别全加
  权重写法见本书「权重语法」一章。

═══════════════════ 十五、局部重绘（修图） ═══════════════════
给「修图」面板用。结论来自实测对照，不是社区传闻。

【三条原则】
  1. 蒙版里要写「画什么」
     只给质量词会生成一块无意义色块。写了内容才正常重画。
  2. 提示词只描述蒙版内的东西
     把整图的角色/场景抄进来会分散 attention，让重绘区往那些概念漂。
  3. 负向是修伪影的主力，不是正向
     出现多余手指/糊掉/不匹配的元素，往负向加词去抵消，别往正向堆。

【改动幅度怎么选】按「部位当前状态」，不按部位
  ★ 部位本来就画对时用 0.8 会改坏：手指变尖、鞋子变色
  0.30–0.45   基本正确，只想微调颜色/表情
  0.45–0.55   有小瑕疵，修结构（修手指数量、修眼睛）← 修图最常用
  0.55–0.70   明显崩坏
  0.70–0.90   完全失败，推倒重来
  0.90–1.00   只保留构图

【蒙版两个参数】
  向外扩张   绝不能设 0 —— 实测边界跳变 47.75（正常 5.3），会出现硬边
             修脸/修手 12–20 ／ 修眼睛这类小区域 4–8
  边缘融合   实测 12/24/48 结果几乎相同，保持 12 不用调

【专用模型影响强度】
  0.7–0.9   保持原结构的推荐区间
  0.4–0.6   想大幅改造（再高会锁死结构，实测 0.75 和 0.90 几乎一样）

【融合方式】

  只有重绘区明显色偏（泛绿/泛黄）才换 Poisson。

【为什么颜色一定会变一点】
  纯 VAE 编解码（不重绘不采样）就有 RGB 平均差 1.16/255、最大 31/255。
  这是 latent 补绘的物理下限，参数消不掉。

【token 预算提醒 —— 2026-09-16 用 ComfyUI 自带 tokenizer 实测重写】
  SDXL 每个 CLIP 编码器 77 个位置（CLIP-L 和 CLIP-G 各一套）。
  ★ 结论：**写长了不会丢词，正负向也不互相挤占**。三处都实测过：
    1) 正负极隔离：server.py 里是两个独立 CLIPTextEncode（L1007-1012），
       全图没有任何 ConditioningConcat / ConditioningCombine /
       ConditioningAverage；两者只在 ControlNetApplyAdvanced 与 KSampler
       处成对传入，从不合并。
    2) 超 77 不是截断，是分块：comfy/sd1_clip.py 的 tokenize_with_weights
       按 77 切开，process_tokens 把每块当 batch 单独编码，最后
       ClipTokenWeightEncoder.encode_token_weights（L68）用
       torch.cat(output, dim=-2) 沿序列维度拼回去 —— 一块不丢。
       实测：负向复制 8 遍 = 8 块，末尾内容完整保留。
    3) SDXL 唯一会「按短的切齐」的地方在 sdxl_clip.py：
       cut_to = min(l_out.shape[1], g_out.shape[1])。
       实测 clip_l 与 clip_g 对同一文本块数永远相同（8 遍也是 8:8），
       不会切掉内容。
  实测占用（CLIPTokenizer 计数，含 BOS/EOS）：
      正向  最小 11 / 典型 25 / 较长 67 token
      负向  改动前 58 / 现在 76 token —— 都还是 1 块
  ⇒ 想加负向词就加，不必为了 token 删词。
  ⚠ 没测过、不下结论的部分：分块后每块的位置编码都从 0 重新开始（CLIP 只有 77 个
    位置嵌入），第 78 个 token 往后的「相对位置」信息是丢的。这对出图效果影响多大，
    本项目没做过对照实验。所以「质量词别堆太多」这条经验仍然成立，
    但理由是效果层面，不是「会被截断」。

【负向词真的有用吗 —— 本项目实测】
  做过对照：基础负向 + 真实修复词 vs 基础负向 + 同长度乱码词，
  两者对输出的影响几乎一样（42.89 vs 45.57）。
  说明负向词的作用主要来自「占据了 token 改变了采样轨迹」，
  而不是语义上精确地消除了某个东西。
  结论：负向词要写，但不必写长；靠蒙版重绘 + 专用模型修结构更有效。

  **根本不能用**：翻译器会把 `:` 和 `(` 当非法字符拆开，提示词直接变垃圾
  （只剩 `(flat` 这种碎片）。下面是唯一验证过能用的写法。

【唯一可用的写法：英文标签 + 多层括号】
    ((flat color))          → 1.21
    (((flat color)))        → 1.331
    ((((flat color))))      → 1.4641
    (((((flat color)))))    → 1.61051

  每多包一层括号 ×1.1。想要更高就继续加层，没有上限写法。
  这是 ComfyUI 的 A1111 兼容语法，本程序会把这串英文**原样透传**。

【四条硬性规则】
  1. 括号里必须是**英文**。中文包进去会被吃掉：
         ((平涂))   →  实际只得到 flat color，权重还是 1.0，等于白写
     正确写法：((flat color))
  2. **不能用 `:` 指定精确权重**。ComfyUI 本身支持 (tag:1.4)，但本程序的
     翻译器会把它拆碎。想要 1.4 做不到，只能用 1.331 或 1.4641 这种档位。
  3. **不能用 `*`**。((flat color)*1.3) 会坏成 ((flat。
  4. **加权词必须用逗号和其他词隔开，不能只靠空格**。
     一个括号里只放一个标签；要加权两个就写两组括号。
     对错例子见下面的对照表。

【中文和英文混写是可以的】
  中文照常写，只有**要加权的那个词**写成英文括号形式，中间用逗号隔开。
  下面「你写的」和「实际得到」成对看（这几行故意不用箭头，免得被
  词表自检脚本当成「中文词条映射」去逐条核对）：

      你写的                              实际得到的英文
      ──────────────────────────────────────────────────────────────
      少女, ((flat color)), 微笑            1girl, ((flat color)), smile
      少女, (((flat color))), 微笑, 银发      1girl, (((flat color))), smile, silver hair
      平涂, ((anime coloring))            flat color, ((anime coloring))
      少女, ((flat color)), ((anime coloring)), 微笑
                                        1girl, ((flat color)), ((anime coloring)), smile
      少女 ((flat color)) 微笑  ← 只用空格  1girl, ((flat, color)), smile
                                        ✗ 括号里被插进了逗号，坏了

【只增不减】
  括号只能加强。想**减弱**某个词，本程序没有可用写法 ——
  改用别的办法：把它从正向删掉，或写进负向提示词。

【实测对照表】
  你写的                        结果
  ((flat color))               1.21                        ✅
  (((flat color)))             1.331                       ✅
  ((blurry))                   1.21                        ✅ 单词标签也行
  ((cropped))                  1.21                        ✅ 负向词同样有效
  1girl, ((flat color)), solo  正常，flat color = 1.21       ✅
  少女, ((flat color)), 微笑     正常                         ✅
  ((平涂))                      flat color，权重 1.0         ❌ 括号被吃
  (flat color:1.4)             (flat，垃圾                  ❌
  ((flat_color:1.4))           空，整段丢弃                 ❌
  ((flat color)*1.3)           ((flat，垃圾                 ❌
  ((flat color)                1.1（括号没闭合，别这么写）    ⚠

【什么时候值得用】
  提示词被 LoRA 压住时。但要说清楚原理，免得白费力气：
  LoRA 改的是**模型权重**，提示词改的是**条件引导**，两者不在一个层级。
  加括号能帮上忙，但上限不高。
  真要对抗 LoRA，用同层级的武器更有效 —— 挂一个画风 LoRA 去对冲。

常见问题
    图糊、细节少        → steps 调到 32；负向加 blurry
    不听提示词          → cfg 调到 7；关键词往前挪
    画面太艳            → cfg 降到 5–5.5
    每张都很像          → 换 seed；多换几个标签
    显存不够            → 分辨率降到 768；关掉草图/参考图


═══════════════════ 二十、LoRA使用要点 ═══════════════════
【触发词怎么工作】
    角色类 LoRA 必须写触发词才会生效，否则等于没挂。
    程序会从 LoRA 文件自带的训练元数据（kohya 的 ss_tag_frequency）
    里自动读出触发词，并自动加进正向提示词，不用你手写。
    UI 里每个 LoRA 下方会显示它的触发词是什么。

    画质增强类 LoRA 通常没有触发词 —— 挂上即生效，靠权重调节。
    （本机的 add_detail 就是这种，它没有任何元数据）

【权重】
    类型              权重        说明
    角色 / 概念       0.7–0.9     让模型认识特定人物
    画风              0.6–0.8     迁移画师/作品风格
    画质增强          0.5–0.8     提升细节
    多 LoRA 叠加       各 0.4–0.6   最多 3 个，超过基本是负收益

【兼容】
    LoRA 与底模绑定。基于 Illustrious 训练的只能配 Illustrious 系底模，
    丢进 SDXL-Turbo 或 Pony 会崩坏或完全无效。下载前先看页面的「底模」标注。


═══════════════════ 二十一、手动放大 ═══════════════════
UI 右侧「最近产出」面板，每张图左下角有「放大」按钮。

推荐流程：
    生成 → 看效果 → 不满意就换 seed 重生成 → 满意了再点放大

放大倍数可选 1.5× / 2× / 3× / 4×，默认 2×（640→1280 约 6 秒）。

为什么不用直接生成 2K？
    直接生成 2048 需要约 100 秒，而 1024 生成 + 放大到 2048 只要 30 秒左右。
